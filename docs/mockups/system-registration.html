    Probe results are pre-filled, not auto-applied. A wrong guess sends power to the wrong box or drops an app launch, and that is painful to diagnose — so the role stays a confirm step.

    Controller remote  
    What the controller is. A remote analog, not a second UI. The hub tile grid lives on the big screen — on an all-in-one that's the display's kiosk browser, on a split system it's the sideloaded shell app on the streamer. The controller just sends key events.
    • Home — foregrounds the hub. On a split system that is am start on the streamer's shell app, not the Google TV launcher.
    • Volume / Mute — routed to the display, not the streamer.
    • Inputs — optional per system. Same action as the TV Inputs tile on the hub. Hidden when the system has nothing worth switching to.
    • Omitted on purpose — Assistant mic, app hotkeys, channel up/down, number pad, settings gear.
    Icons. Drawn here to match Google's Material Symbols set. For the real build we should self-host the actual Material Symbols files rather than hotlink Google Fonts, so a controller still renders if campus DNS or the CDN is having a day.
